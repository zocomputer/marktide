# Chunk-size sweep for lxml target parser feed()

Date: 2026-06-17
Bead: `zo-1fp.6`

## Summary

Measured `lxml.etree.HTMLParser(target=CountingTarget(), huge_tree=True).feed(...)` on a worker thread while the main thread ran a 1ms asyncio heartbeat. The 50 MiB input was `benchmarks/spikes/sample_50mb.html` (generated by the existing spike helper; gitignored).

All chunk sizes kept p99 heartbeat jitter under 0.5ms, effectively at the idle floor (~0.32ms p99). Throughput was flat from 16 KiB through 1 MiB (~67 MiB/s), with 4 KiB slightly slower (~65.5 MiB/s) due to feed-call overhead. The sweep supports a **64 KiB default chunk size**: it is on the throughput plateau, bounds per-feed latency/cancellation granularity far below 1 MiB, and avoids the extra call density of 4 KiB/16 KiB.

## Environment

- Python: `3.12.13`
- Heartbeat target: `1.0ms`
- Input: `benchmarks/spikes/sample_50mb.html` (50.00 MiB / 52429809 bytes)
- Idle heartbeat floor: p50 `0.277ms`, p95 `0.305ms`, p99 `0.320ms`, max `0.355ms`

## Results

| chunk_size | feed calls | parse time | throughput | heartbeat p50 | heartbeat p95 | heartbeat p99 | max jitter |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 4 KiB | 12801 | 0.763s | 65.5 MiB/s | 0.302ms | 0.360ms | 0.428ms | 1.078ms |
| 16 KiB | 3201 | 0.738s | 67.8 MiB/s | 0.302ms | 0.358ms | 0.395ms | 0.432ms |
| 64 KiB | 801 | 0.747s | 67.0 MiB/s | 0.299ms | 0.362ms | 0.429ms | 0.598ms |
| 256 KiB | 201 | 0.745s | 67.1 MiB/s | 0.301ms | 0.364ms | 0.439ms | 0.867ms |
| 1024 KiB | 51 | 0.745s | 67.1 MiB/s | 0.303ms | 0.362ms | 0.402ms | 1.408ms |

## Interpretation for design.md

- `4 KiB` has the densest callback/feed-call control and a still-excellent p99 jitter, but it costs about 2-2.5% throughput relative to the plateau and performs 12,801 feed calls for the 50 MiB sample.
- `16 KiB`, `64 KiB`, `256 KiB`, and `1 MiB` are effectively tied on throughput and p99 jitter in this target-parser parse-only sweep.
- `64 KiB` is the best default because it lands on the throughput plateau while keeping cancellation/progress/checkpoint boundaries 16x more frequent than `1 MiB` and without the feed-call density of `4 KiB`.
- This sweep covers parser feed/callback behavior only. Python tree-walk and Markdown emission still need explicit cooperative yields because `benchmarks/spikes/gil_probe_output.txt` shows those stages hold the GIL.
